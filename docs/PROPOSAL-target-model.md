# 提案：把「选载荷」从机型卡改成内核线 + 自动检测

> 状态：**提案，未实现**。目标是把当前 72 条 `FirmwareVersion` 条目收敛到 ~10 个内核线 target，
> 并把设置页、关于页从"一屏铺开"改成"3 个入口 + 子页"。

## 1. 现在为什么冗杂

`FirmwareVersion` 一条 = 一个机型 + 一个构建 + 一个引擎 + 一个 ksud + tested 标记。
但真正决定"能不能打、该用哪份载荷"的只有三件事：

1. **内核构建号**（如 `34343818`）——决定 98260 的载荷是否适用
2. **引擎**（98260 / 43499）——决定走哪条链
3. **ksud 驱动**（3.2.5 / 3.3.0）——决定 late-load 用哪份驱动

机型名、区域、系列都只是**别名**。现在每加一个 userspace 更新（EZJB/EZJD）、每加一台同内核机器
（S928U1/S921W），就要加一条，条目数线性膨胀：

| 现状 | 数量 |
|---|---|
| `FirmwareVersion` 条目 | **72** |
| 其中 98260 条目 | 6 |
| 其中 43499 条目 | 66（大量同载荷重复：S9280DZF2/S9260DZF2/S9210DZF2…） |
| 设置页分组 / 条目 | 7 组 / ~20 项 |
| 关于页分组 | 设备信息 + 8 条 FAQ + 许可 + 论坛 |

## 2. 目标数据模型

```kotlin
data class Target(
    val kernelLine: String,          // "6.1.162-34343818"
    val kernelBuild: String?,        // "34343818"；null = 按 payload 逐构建定标（43499）
    val payloads: Map<Engine, Payload>,   // 98260: 通用 libtimer；43499: cve-2026-43499-<build>
    val ksud: Map<KsuDriver, String>,
    val devices: List<DeviceAlias>,  // 只用于显示/搜索
    val tested: Boolean,
    val note: String,
)

data class DeviceAlias(val model: String, val region: Region, val builds: List<String>)
```

## 3. UI 方案

### 3.1 机型页：自动检测卡 + 可折叠的"换机型"

```
┌─────────────────────────────────────────────┐
│  当前设备（自动检测）                        │
│  SM-S9280 · S9280ZHU6EZJB                    │
│  kernel 6.1.162-34343818                     │
│  推荐：98260 UAF · 驱动 3.2.5 · 已实测        │
│  载荷：samtimer/libtimer (kernel 34343818)   │
│                                             │
│              [ 开始 Root ]                  │
│  ▸ 高级（改引擎/驱动）                       │
└─────────────────────────────────────────────┘

▸ 换机型 / 手动选择
  按内核线分组（不是按系列）：
  6.1.162 · 34343818   98260   已实测
    └ S9280 / S928B / S921E / S921W / S928U1 …
  6.1.145 · 3254743    43499   已实测
    └ S9280 / S9210 / S9260 / S928B …
  6.1.128 · 31999054   43499   未验证
  6.6.98               43499   未验证
  ▸ 其他内核线（未验证移植，需开启"未经测试的载荷"）
```

- 覆盖判断继续用**内核构建号**（已实现，见 `coversBuild`）
- 构建串只在设备别名里出现，不再影响条目数量
- 搜索框支持直接输入构建号（`EZJD` / `34343818`）

### 3.2 设置页：3 个入口，主页 ≤ 6 项

| 页 | 内容 |
|---|---|
| **常用** | 授权方式（Shizuku/无线调试）· 自动熄屏 · 运行日志共享 · 检查更新 |
| **高级**（子页） | 默认引擎 · 默认驱动 · 禁用 KSU 模块 · SELinux 策略 · Raw log · 启用未测试载荷 |
| **诊断与关于**（子页） | 版本/build · 日志导出 · 安装 ID · 隐私政策 · 开源许可 · 调试模式（版本连点 7 下） |

规则：一次性/排障用的开关全部下沉到「高级」；设置主页不再出现 SectionLabel 堆叠。

### 3.3 关于页：一屏卡片 + 折叠

       双引擎临时 root

[检查更新]  [隐私政策]  [开源许可]

许可证全文从当前页移到子页（异步加载 + 失败重试仍保留）。

## 4. 迁移

1. `FirmwareVersion` 保留为"别名层"：旧条目名映射到新 Target（旧偏好、旧日志、服务端清单不失效）
2. 新 UI 先与旧列表并存一个版本；旧列表标记「经典视图」供回退
3. 服务端 `payloads.json` 结构不变（仍按 asset 下发），只是本地 Target 引用它

## 5. 实施顺序

| 阶段 | 内容 | 风险 |
|---|---|---|
| 1 | Target 模型 + 自动检测卡（机型页顶部） | 低（新增，不动旧列表） |
| 2 | 换机型页按内核线分组 + 搜索 | 中（UI 重排） |
| 3 | 设置页 3 入口 + 高级子页 | 低（纯导航） |
| 4 | 关于页收敛 + FAQ 子页 | 低 |
| 5 | 移除旧 Flat 列表（保留经典视图开关） | 低 |

建议先做 **1 + 2**（payload 选择是持续膨胀的部分），3/4 可以同版本带上。
